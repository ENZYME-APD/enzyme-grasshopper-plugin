Method, assumptions and simplifications

The same notes appear in the component's Info output.

Method

  1. Only closed, planar curves are used. Each one is divided into n equal-length parts, n = max(4, ceil(length / modSize)), so the real spacing is length / n (at most modSize).
  2. At each division point the horizontal direction perpendicular to the curve is found (curve-plane normal × tangent) and turned to point away from the curve's area centroid.
  3. A divLine runs from the point outwards by tDepth.
  4. A transom is a flat rectangular surface on that line, rising tHeight along the curve-plane normal (turned to point up).
  5. modSize, tDepth and tHeight are matched by branch path and item index; a single value applies to all; missing values use defaults 1.0 m, 0.2 m and 0.1 m. Outputs keep the input path plus the curve index.

Assumptions

  • Curves are closed floor or facade outlines drawn in a horizontal plane; units are metres.
  • Outward means away from the centroid, which is right for convex shapes.

Simplifications and limits

  • Transoms are zero-thickness surfaces, not solid profiles.
  • No corner handling: fins sit only at equal divisions, not at the curve's corners.

Workflow

  • Floor outlines (for example Facade JSON Parser BoundsClosed) -> curves; transoms -> Custom Preview or bake.
