Fast CFD

A multi-threaded 2.5D Terrain-Following Grid Fluid Solver for fast urban aerodynamic and pedestrian wind comfort analysis.

Site Analysis Nickname: FastCFD Version: 1.10.75+

Overview

Fast CFD is an ultra-fast Eulerian fluid dynamics simulator written directly in native C# for Rhino and Grasshopper. It numerically resolves the incompressible Navier-Stokes equations across a 2.5D terrain-following grid, accurately predicting Venturi channeling, corner accelerations, stagnation zones, and recirculating wake eddies around urban structures.

Designed specifically for early-stage massing design and site planning, Fast CFD runs in tens of milliseconds rather than hours, allowing interactive manipulation via Grasshopper sliders without locking the Rhino interface.

Key Features & Numerical Physics

⚡ Multi-Core Parallelization

Employs thread-safe Parallel.For loops across all solver stages (Grid Draping, Advection, Diffusion, and Poisson Pressure Projection) with deterministic ping-pong buffers, delivering 5x–15x speedups on multi-core systems.

🏢 Zero-Gradient Neumann Boundaries

Enforces ∂p/∂n = 0 at building obstacle facets. Incoming air forms realistic physical stagnation pressure and smoothly deflects around corners, completely eliminating artificial boundary vacuum sinks.

🚶 Pedestrian Comfort (Lawson Scale)

Computes local shear strain tensors to estimate sub-grid Turbulent Kinetic Energy (TKE) and Turbulence Intensity (TI), categorizing urban spaces into Sitting, Standing, Strolling, and Uncomfortable pedestrian zones.

📦 Pre-Cached Spatial Indexing

Context geometry bounding boxes are cached once before grid construction, bypassing hundreds of thousands of redundant 3D point-in-mesh raycasts and eliminating UI lag during initial grid draping.

Lawson Pedestrian Comfort Categories (LDDC Criteria)

  • ☕ Sitting / Outdoor Dining (< 4.0 m/s): Calm microclimate suitable for long-term sedentary activities, cafes, and restaurant terraces.
  • 🧍 Standing / Pedestrian Waiting (< 6.0 m/s): Gentle breeze suitable for building entrances, bus stops, and plazas.
  • 🚶 Strolling / Leisure Walking (< 8.0 m/s): Comfortable for pedestrian boulevards, promenades, and shopping streets.
  • 💼 Business Walking / Transit (< 10.0 m/s): Fast-paced walking along transit corridors, office thoroughfares, and commuter routes.
  • ⚠️ Uncomfortable / High Gusts (> 10.0 m/s): Strong winds with potential wind turbulence that compromise pedestrian comfort.

Inputs (13)

  • TerrainMesh (Mesh): Input topography mesh over which the 2.5D simulation sheet drapes.
  • ContextMeshes (Mesh list, optional): Closed building and site massing meshes acting as aerodynamic obstacles.
  • WindVector (Vector): Cardinal orientation of the prevailing wind (e.g. (1, 1, 0) for NE wind).
  • WindSpeed (Number): Baseline meteorological wind speed magnitude in m/s (default: 10.0).
  • CellSize (Number): Spatial resolution of the Eulerian grid in meters (default: 4.0). Smaller cells increase spatial resolution.
  • Iterations (Integer): Advection and diffusion time steps (default: 50). Automatically adapts to domain scale if lower than minimum domain flush.
  • AnalysisHeight (Number): Offset in meters above terrain level for pedestrian comfort evaluation (default: 1.5m).
  • Viscosity (Number): Fluid kinematic viscosity in m²/s (default: 0.1). Scaled independently of grid cell size.
  • Friction (Number / List, optional): Surface aerodynamic drag coefficient (0.0 to 1.0) simulating rough terrain, vegetation, or paving.
  • ComfortThreshold (Number): User-defined comfort threshold in m/s (default: 5.0).
  • BoundaryMask (Curve, optional): Closed curve to restrict the simulation domain and lock grid coordinates.
  • Colors (Colour list, optional): Custom gradient palette for velocity heatmap visualization.
  • WindRefHeight (Number, optional): Meteorological measurement height for input WindSpeed in meters (default: 10.0m). Scales to pedestrian level via atmospheric boundary layer (ABL) power law.

Outputs (7)

  • WindMesh (Mesh): Continuous vertex-colored mesh displaying the terrain-projected wind velocity heatmap.
  • Points (Point list): Evaluated grid point positions at pedestrian analysis height.
  • WindVectors (Vector list): Local velocity vectors (m/s) indicating local direction and speed.
  • Colors (Colour list): Color values assigned to each grid point and vector.
  • Speeds (Number list): Scalar wind speed magnitude (m/s) at each grid cell.
  • Dashboard Data (Text / JSON): Structured JSON payload compatible with the Analysis Dashboard HUD component.
  • Info (Text): Detailed performance log, domain statistics, Lawson comfort breakdown, and scientific notes.

Best Practices & Guidelines

  • Anchor with BoundaryMask: The Eulerian grid anchors to the bounding box of your geometry. When comparing architectural massing options, always supply a fixed BoundaryMask curve so that cell boundaries do not shift between iterations.
  • Resolution vs. Speed: For quick massing sweeps, a CellSize of 3.0m–5.0m provides near-instant interactive updates. For final presentation graphics, reduce CellSize to 1.5m–2.0m.
  • 2.5D Assumption: The solver computes a terrain-following 2D layer. It excels at simulating horizontal Venturi effects, gap flows, and wake eddies, but does not capture 3D vertical downwash vortices from tall skyscrapers.
