Export Named Views

Exports Rhino Named Views to image files with custom ViewCapture settings.

Utilities Nickname: ExportViews

Overview

Exports Rhino Named Views to image files with custom ViewCapture settings.

Inputs (15)

  • Run (Boolean): Set to true to export the views.
  • Views (Text): Names of the views to export. If empty, exports ALL named views.
  • Display Style (Text): Optional. Name of the Display Mode (e.g., 'Rendered'). Leaves active if empty.
  • Layer State (Text): Optional. Name of the saved Layer State to restore. Leaves active if empty.
  • Directory (Text): Folder path to save the images.
  • Prefix (Text): Prefix for the output filenames (optional).
  • Suffix (Text): Suffix for the output filenames (optional).
  • Format (Text): Image format: png, jpg, bmp, tiff.
  • Width (Integer): Image width in pixels.
  • Height (Integer): Image height in pixels.
  • DPI (Integer): Print DPI metadata embedded into the image.
  • Grid (Boolean): Show Grid.
  • World Axes (Boolean): Show World Axes.
  • CPlane Axes (Boolean): Show CPlane Axes.
  • Transparent (Boolean): Transparent background (PNG only).

Outputs (2)

  • Saved Files (Text): Paths to the saved image files.
  • Info (Text): Component information and interpretation

Method, assumptions and simplifications

The same notes appear in the component's Info output.

Method

  1. When Run is True it collects the Named Views given in Views (all named views if empty), optionally sets the active viewport to Display Style and restores Layer State.
  2. For each view it pushes the view onto the active viewport, captures it with Rhino ViewCapture at Width × Height pixels (grid, world axes and CPlane axes on or off, optional transparent background for PNG and TIFF only, ignored for JPG and BMP which have no alpha channel) and saves it as png, jpg, bmp or tif with DPI written as metadata.
  3. Files are named Prefix_view name_Suffix in Directory (Desktop if empty, created if missing); afterwards the original view, display mode and layer state are restored.

Assumptions

  • The active viewport is the one to use; Display Style and Layer State names match existing ones (case-insensitive).

Simplifications and limits

  • The capture uses the active viewport projection with the requested pixel size, so a view with a different aspect ratio is cropped or extended. Exports run on every solution while Run stays True.

Workflow

  • Paper Size To Pixels -> Width, Height, DPI.
