Urban Wind Vector Engine HT (Beta)

Simulates urban wind fields using terrain-parallel raycasting. Outputs a perfectly flat, crisp XY pixel-screen heatmap at a custom elevation.

Site Analysis Nickname: WindEngineHTVer

Overview

Simulates urban wind fields using terrain-parallel raycasting. Outputs a perfectly flat, crisp XY pixel-screen heatmap at a custom elevation.

Inputs (19)

  • Run (Boolean): Global execution toggle switch
  • TerrainMesh (Mesh): The underlying site topography
  • ContextBuildings (Mesh): Lightweight mesh context structures
  • WindDirection (Vector): Travel vector of incoming air
  • WindSpeed (Number): Baseline velocity metric
  • AnalysisHeight (Number): Human pedestrian offset
  • GridSpacing (Number): Resolution size of pixel elements
  • CustomColors (Colour): Custom color spectrum override
  • HeatmapHeight (Number): Z offset applied to the heatmap: added to the terrain bounding box top in Flat mode (DrapeHeatmap=false), or added to each point's own local terrain height in Drape mode (DrapeHeatmap=true)
  • WakeLengthRatio (Number): Wake length as a multiple of the obstructing building's height (typical near-wake range 6-8x)
  • SlopeSpeedup (Number): Coefficient controlling how much upward terrain slope accelerates wind (0 = no slope effect)
  • CornerTangency (Number): How tangent (0-1) wind must be to a wall before corner-channeling kicks in; lower = stricter
  • CornerBoost (Number): Speed boost coefficient applied when wind channels around a building corner
  • GapBoost (Number): Extra speed boost applied when a point is squeezed between two facing building walls (venturi/tunneling), scaled by how narrow the gap is
  • Iterations (Integer): Relaxation passes per point: each pass re-evaluates wake/corner/gap using the previous pass's own direction, letting a point settle through multiple sequential building interactions instead of a single snapshot. 1 = original single-pass behavior
  • Damping (Number): Blend factor (0-1) between a point's previous iteration and its newly computed one. Lower = slower, more stable convergence; 1.0 = no damping (replace outright each pass)
  • DrapeHeatmap (Boolean): true = heatmap follows terrain relief, offset from each point's own local ground height. false = a single flat plane, offset from the terrain's bounding-box top
  • SeedBox (Box): Optional bounding box - every valid analysis grid point inside it is used as a streamline seed instead of the default sparse grid sampling
  • StreamlineMaxSteps (Integer): Safety ceiling on streamline length. A streamline normally stops on its own once it exits the mesh, goes solid, or its speed dies out - this only guards against a pathological case looping forever

Outputs (9)

  • VelocityHeatmap (Mesh): Flat, unwelded crisp horizontal pixel-tile matrix
  • WindVectors (Line): Spatial direction markers
  • VectorColors (Colour): Velocity color map matching lines
  • Streamlines (Curve): Continuous particle flow paths
  • TagPoints (Point): Anchor coordinates for Text Tag
  • PlainMesh (Mesh): Original topography mesh without vertex colors
  • VelocityValues (Number): Raw unformatted velocity values, aligned with WindVectors
  • Info (Text): Component information and interpretation
  • Dashboard Data (Text): JSON legend payload (min/max speed + the actual color ramp in use) - feed directly into the Legend Geometry component's Color Legend input
