Global Flood Engine

Simulates rainfall accumulation pooling into local valleys and depressions.

Site Analysis Nickname: GlobalFlood

Overview

Simulates rainfall accumulation pooling into local valleys and depressions.

Inputs (7)

  • TerrainMesh (Mesh): Input Terrain Mesh
  • Rainfall (Number): Rainfall intensity in Liters/m2/hour (mm/h)
  • Duration (Number): Duration of the rain event in hours
  • Iterations (Integer): Simulation steps for water flow
  • Runoff Coefficient (Number): Multiplier for rainfall (0.0 to 1.0). 1.0 = concrete (no absorption). Can be a single value or a list matching the mesh vertices.
  • Boundary Condition (Integer): 0 = Closed (water pools at edges), 1 = Open (water drains off edges)
  • Run (Boolean): Optional. False = skip the analysis and keep showing the last results (cached). Share one toggle with the Analysis Dashboard to switch everything on/off together.

Outputs (4)

  • FloodMesh (Mesh): Flooded terrain heatmap mesh
  • WaterDepths (Number): Water depths at each vertex in meters
  • AnalysisPoints (Point): Points corresponding to the water depth values
  • Info (Text): Component information and interpretation

Method, assumptions and simplifications

The same notes appear in the component's Info output.

Method

  1. Every mesh vertex starts with a water depth d = Rainfall × Duration / 1000 × Runoff Coefficient (in m; Rainfall in mm/h, Duration in h). Coefficients are a single value or one per mesh vertex.
  2. Each iteration, every wet vertex (d > 0.1 mm) finds the connected neighbour with the lowest water level (ground Z + depth). If it is lower, half the level difference is moved to it, limited to the water the vertex holds.
  3. With Boundary Condition 1 (open), the water at naked-edge vertices is set to 0 after every iteration, so it drains off the model. With 0 (closed) it stays.
  4. The loop stops after Iterations steps or when no water moved.
  5. WaterDepths are the final depths per mesh vertex; FloodMesh is coloured light grey below 0.01 m and from cyan to dark blue by depth relative to the maximum.

Assumptions

  • Every vertex stands for the same plan area, so moving depth between vertices conserves volume only on an evenly spaced mesh.
  • All rain falls at once at the start; Duration only scales the total depth.
  • Z is in metres and the mesh is a terrain (one height per plan location).

Simplifications and limits

  • No infiltration over time, no flow velocity, roughness or travel time; Iterations are not time steps.
  • Water moves at most one mesh edge per iteration, to one neighbour only, so on large or fine meshes the result depends on Iterations and may not reach equilibrium.
  • No drainage network, buildings or culverts.

Workflow

  • Terrain Mesher or a site mesh -> TerrainMesh.
  • WaterDepths with AnalysisPoints -> legend, dashboard or threshold filters.
